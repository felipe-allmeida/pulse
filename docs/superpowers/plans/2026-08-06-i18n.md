# i18n (pt-BR / en-US) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship full pt-BR/en-US internationalization of the pulse web app (UI chrome + data-driven content) plus an AI assistant that answers in the user's active language.

**Architecture:** `react-i18next` for UI strings (namespaced JSON per locale, browser detection + localStorage persistence, `en` fallback); a `LocalizedString` shape + `useLocalized()` hook for data-driven content in the typed modules; a header PT/EN toggle; and a small backend change so `POST /api/ask` responds in the requested locale while staying grounded in the English `profile.md`.

**Tech Stack:** React 19 + Vite + TanStack Router + shadcn + Tailwind v4 + vitest; `i18next` + `react-i18next` + `i18next-browser-languagedetector`; .NET 10 minimal API (ask endpoint) + xUnit.

## Global Constraints

- **pnpm**; TS strict, no `any`; English default (`en`), Portuguese `pt-BR`.
- **Hard gate every task:** `pnpm -C web build` + `pnpm -C web exec tsc --noEmit` + `pnpm -C web test` green; for backend-touching tasks also `dotnet build` + `dotnet test` green.
- **Confidentiality:** the projects' public/private invariant stays STRUCTURAL on `content/projects.ts` (`visibility`/`links` untranslated); the existing `content.test.ts` must keep passing. Ulbra pt-BR copy stays as high-level as the English (product/role/stack only — no proprietary detail).
- **Content proper nouns** (`profile.name`, `project.name`, skill names) stay plain strings — not translated.
- **TDD**: failing test first every task. Detection order `localStorage → navigator → 'en'`; localStorage key `pulse.lang`.
- Translations are drafted in-task and **flagged for Felipe's review** (natural pt-BR; keep idiomatic tech terms like "deploy"/"backend").

- [ ] **Step 3: implement** — `use-localized.ts`:
```ts
import { useTranslation } from 'react-i18next';
import type { Locale, LocalizedString } from '@/content/types';

export function useLocalized() {
  const { i18n } = useTranslation();
  const locale = (i18n.language as Locale) in { en: 1, 'pt-BR': 1 } ? (i18n.language as Locale) : 'en';
  return (v: LocalizedString): string => v[locale] || v.en;
}
```
